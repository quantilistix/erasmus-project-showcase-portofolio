# Network and display audit

The existing agent has collapsed controls. A read-only, no-learning 180-frame GPU audit found all eight keys active on all 180 frames in the repository checkpoint (40,580 saved frames). The historical IDE checkpoint (249,603 saved frames) pressed all eight on 159/180 frames; other combinations still held six or seven keys. Raw key scores ranged roughly 0.29–1.19 in the IDE checkpoint, rather than behaving as calibrated probabilities. See `maze-network-audit.jsonl`. These results establish a real behavioral problem; earlier numerical tests did not establish successful learning.

## Corrections

The actor target used the same magnitude of update with opposite sign for every unpressed button. When a sparse exploratory combination received negative advantage, that directly reinforced all other buttons. Unpressed buttons now carry zero direct actor-loss weight. Only executed buttons receive the bounded advantage-dependent target update. A regression verifies that a missed exploratory shot decreases the held firing bias without directly increasing an unpressed movement bias. This is a limited correction to a heuristic learner, not proof of a converged policy. Existing collapsed parameters have not been reset or automatically retrained.

Default checkpoint paths were relative to the working directory, creating two experiments. Default resolution is now independent of working directory. A pre-existing IDE checkpoint under `src/ArcadeLab/artifacts/maze` is preferred to preserve its progress; otherwise the repository `artifacts/maze` is used. Startup prints the absolute path and warns about an alternate historical copy. Explicit `--checkpoint` remains available. Neither historical checkpoint was modified by the audit or viewer checks.

There are 2,907 logical input units: 1,296 current RGB channels (384 world rays plus 48 status pixels), historical zeroed ports, stereo sound features, button feedback, sensations and clock. There are 23 logical output units: eight key scores, fourteen auxiliary outputs (value, reward and twelve predicted view bins), and one unused compatibility port. Every logical unit has two nonnegative rate channels. Extra outputs are not extra keys.

The original diagram showed only twelve sampled inputs, which made the counts misleading. Drawing every neuron as a tiny cell then made the graph unreadable. The final overview instead explicitly labels eight sampled input units, six units per hidden layer, the actual full layer counts, eight keys and a separate auxiliary group. Every displayed edge exists in the model. The view is a sample, not a full four-million-edge diagram. High-resolution text scaling and missing font glyphs were corrected. Hover values retain exact activations/weights; colors are display-scaled.

Exploration teacher targets are 24 per new cell and 8 per new region. Raising both rewards and the bar maximum by eight left normalized bar widths unchanged. Absolute schedule, payout and remaining earned credit now appear separately, along with absolute predicted pleasure and ideal pleasure. Play deliberately uses a frozen learned translator and receives no ideal novelty reward; it needs further reward training to reflect a changed schedule. A restart is necessary to run a newly built binary.

## Evidence and limitations

Release build passed. All 10,835 assertions passed with Vulkan validation, including reward totals, no reward on revisits, exact combat rewards, persistent state, fixed threshold, the unpressed-button regression and checkpoint-path resolution. Final graph changes were checked in a GLFW/Vulkan run and an app-frame capture. Validation logs are `maze-audit-build.log`, `maze-audit-validation.log`, `maze-audit-viewer-validation.log`.

This still uses persistent live propagation with a stateless surrogate learning objective. The audited live-versus-stateless control RMSE was approximately 0.026 in the repository checkpoint and 0.056 in the IDE checkpoint over those trajectories. That is not temporal backpropagation or a full predictive-coding error-neuron algorithm. Removing the incorrect unpressed-button reinforcement does not resolve all credit-assignment, gain-saturation, representation-drift or partial-observation issues. The agent has not been shown to learn reliable maze behavior. Thresholded policy outputs are deterministic; independent controls do not imply independent random presses.
