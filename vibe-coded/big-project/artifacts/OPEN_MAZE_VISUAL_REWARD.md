# Open-maze progression and visual reward

Procedural geometry now advances every five saved completions in both modes. Stages 1–5 use corridor widths 3, 3, 2, 2, 1 and room sides 9–13, 7–11, 5–9, 3–7, 3. The fifth stage uses the former generator. Rooms may be clipped at the outer border. The world stays 41×41 and every stage retains reachable floors, solid borders, an exit at maximum path distance, supply scaling and route-dependent episode time. Early stages also use a lower encounter density. Deaths and elapsed frames do not advance geometry. A stage change takes effect on the next reset, and loading restores the completion counter before generating that maze.

Across eight seeds, stage-one layouts had 8,684 walkable cells in aggregate versus 6,918 in stage five, about 25.5% more. The number of floor cells with a completely open surrounding 3×3 square was 5,211 versus 92. These measure space, not learned exploration performance.

The old combined reward head was not reliably learning the spatial-variety contribution. The score now includes a 50% chromatic-diversity term using normalized hue-like color ratios, alongside 25% spatial variation and 25% structure. Small spatial bins suppress speckle, the HUD is excluded, and chromatic diversity discounts brightness attenuation. Controlled tests distinguish multiple hues from flat gray and preserve chromatic diversity under darkening.

Visual reward has a separate nonnegative linear readout. A scalar coefficient starts at zero and is supervised by online least squares on visual targets during training. Its inference is `coefficient * speed * currentVariety`. The event head learns the residual pleasure target with the visual contribution removed, and continues to learn pain. Its input summary is masked so the direct feature belongs to the visual branch. Both components freeze in play; no ideal bonus is inserted in play. Old checkpoints start with an untrained visual coefficient and need a training run/save. Session version 7 stores the learned coefficient and supervised sample count in maze.json; reward.json alone no longer contains the complete composed reward predictor.

The viewer prints predicted visual contribution separately from ideal bonus; logs also show chromatic diversity and event pleasure. In the temporary hardware training check, variety 0.1873 produced predicted visual reward 0.09365 and ideal visual bonus 0.09365. A captured earlier frame showed variety 0.342 and predicted/ideal contributions both 0.1711. Total pleasure also contains event predictions and is capped at 32, so total changes across different scenes are not a pure measure of color diversity.

Release build and all 11,180 assertions passed with Vulkan validation. The new 293-assertion suite covers all five stage geometries, seed variation, connectivity, actual increased turning space, completion boundaries, learning calibration, color attenuation, saved progression and both frozen reward components. A 90-frame GLFW/Vulkan training run and captured frame verified the display. Logs: open-maze-build.log, open-maze-validation.log, open-maze-viewer-validation.log.

Checks and the GUI run did not save changes to user checkpoints. Improved autonomous behavior has not been established. These changes are to the game and current reward system; the agreed paired-error predictive-coding replacement remains a specification, as stated in the main README.
