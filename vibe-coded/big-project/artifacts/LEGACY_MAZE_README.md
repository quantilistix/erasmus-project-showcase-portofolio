# Artificial Brain: Neural Maze

A C# learning experiment with a separate [NeuralGraph library](src/NeuralGraph/README.md), Vulkan GPU compute, and a GLFW/Vulkan game window. The game is a **2D maze shooter**. The agent sees a **one-dimensional first-person RGB sensor line**, receives stereo raw sound and per-ear FFT magnitudes, and operates discrete controls. Walls occlude vision. The map on the left is for the human observer and is never a network input.

**Architecture status:** the [agreed predictive-coding specification](src/NeuralGraph/PREDICTIVE_CODING.md) defines normal/error neuron pairs, fixed local connections, tied forward/negated-backward weights, accumulating activity and local plasticity. Its total error is `sum(error[i]²)`, used only for statistics. The current executable still uses the earlier learning mechanism documented below; the specification is not yet implemented. Existing training may be discarded for the replacement, as authorized by the user.

## Run

Requires .NET 10, Vulkan drivers, GLFW 3 and optionally OpenAL for sound playback. On Debian/Ubuntu the native packages include `libvulkan1`, `libglfw3`, and `libopenal1`. The checked-in SPIR-V shaders allow building without a shader compiler; `scripts/compile-shaders.sh` rebuilds them when GLSL changes.

The viewer starts **maximized**, with a 1600×1000 default window size. You can resize or unmaximize it normally.

There are exactly two running modes:

```bash
# Teach both the policy and the reward translator. Automatically resumes saved maze training.
dotnet run --project src/ArcadeLab -c Release -- --train

# Freeze the reward translator. The main network STILL learns every frame.
dotnet run --project src/ArcadeLab -c Release -- --play
```

For faster-than-display training:

```bash
dotnet run --project src/ArcadeLab -c Release -- --train --headless --frames 20000
```

Use `--game-speed 0.25` for quarter-speed physics; the default is **half speed**. The learning/display target stays 60 updates/s. Headless execution uses simulation time rather than wall-clock pacing. `--backend cpu` provides a reference fallback. The independent button activation threshold is fixed at 0.5. `--help` lists the configuration options. Play requires an existing checkpoint with reward training updates; this checks that training occurred, not that the model is already competent.

## Game and controls

The full world is a connected procedural **41×41 maze** with rooms, loops, moving enemies, health kits, ammo clips, and an exit. This is about 4.7 times the area of the earlier 19×19 map. Enemy and supply counts scale with walkable area; the exit is placed at the furthest reachable cell. Every episode/reset generates a new layout, and the time budget scales with the route length. Enemies chase/strafe within sight and fire with varying aim, speed and timing. Both sides use travelling projectiles; swept collision substeps stop fast bullets passing through walls or actors. The player has an eight-round magazine, reserve ammunition, a firing cooldown and a timed reload. Sound includes player/enemy footsteps, gunfire, impacts, kills, reloading and pickups. Each event has its own sine voice starting at zero pressure, a smooth 5 ms attack and up to 20 ms release, and a fixed duration. Events overlap instead of abruptly retuning a shared oscillator. The neural sensor samples independent left/right channels at 3,840 Hz, with a separate FFT for each ear. A dedicated audio thread synthesizes the same events continuously as interleaved 48 kHz stereo for playback. Equal-power panning follows the agent's facing direction: enemy footsteps, gunfire and impacts can be heard on the left or right; the agent's own sounds are centered. A short playback queue decouples sound from GPU/render frame timing. Playback pitch and note duration do not change with the FPS setting; pausing fades active notes out. Sound travels by distance; enemy targeting and vision require line of sight.

Maze geometry progresses in both modes according to saved **successful completions**, not elapsed frames or deaths. Every five completions advances one stage; after twenty it uses the original narrow-corridor generator. The current stage applies when the next maze is generated. Rooms and corridors stay connected, borders remain solid, the exit remains the furthest reachable floor and the world stays 41×41.

| Completed mazes | Corridor width | Room side lengths |
| --- | --- | --- |
| 0–4 | 3 tiles | 9–13 tiles |
| 5–9 | 3 tiles | 7–11 tiles |
| 10–14 | 2 tiles | 5–9 tiles |
| 15–19 | 2 tiles | 3–7 tiles |
| 20+ | 1 tile, original layout | 3 tiles |

Room bounds can be clipped at the solid outer border. Early stages have a broad spawn area and sparser enemies; enemy and supply counts still scale with walkable area. Separately, the first 12,000 training frames use weaker enemies, reduced starting health/ammunition and nearby health/ammo opportunities. Deaths/resetting do not advance geometry. Play resumes the same saved completion stage. This is a curriculum within the existing two modes, not an oracle controller.

AI controls are independent held buttons: forward, backward, turn left/right, strafe left/right, fire and reload. Every output strictly above the fixed 0.5 threshold presses its button; multiple buttons can press together. There is no wait output or combined forward/fire output. If none crosses the threshold, no button is forced. Opposing directions cancel, and diagonal movement has normalized speed. Manual controls also support simultaneous keys and still generate learning updates in the selected mode. The eight control indicators are labeled W S A D Q E F X. A large square **TOP VIEW** shows the full maze, the blue player with a white facing arrow, red enemies, health/ammo pickups, exits and moving projectile trails. Dashed lines show the edges and centre of the agent's current field of view, and a muted blue trail shows its recent movement. A color legend identifies the objects. The **CURRENT VIEW** RGB sensor line remains underneath the map with LEFT/RIGHT labels. No previous-view image is supplied to either network or displayed as a second line. These are the exact world-ray colors supplied to the network, rather than a flattened top-down image. Red indicates enemies, green health, gold ammo, cyan exits and bright yellow/orange projectiles. Brightness fades with hit distance using `1 / (1 + 0.12 * distance²)`, so identical objects get darker as they move away while retaining their hue. A centre tick marks the facing direction.

Larger health, magazine and reserve displays sit underneath. Neural frames include 384 RGB world rays followed by 24 health-status and 24 ammo-status RGB pixels; HUD status colors do not dim with world distance. The current frame contains 432 pixels × 3 channels. Former previous-view ports stay clamped to zero for checkpoint compatibility. At narrow window sizes the viewer averages neighboring rays to fit. The top view is observer-only and remains unattenuated for readability; it is never supplied to the neural networks. The right side displays neuron activity, reward bars and stereo waveforms.

Green/blue neuron cells are opposing nonnegative rate populations. The reward bars show learned pleasure (green), learned pain (red), primitive pain (amber) and primitive pleasure trace (blue). Cyan audio plots represent the left ear; pink represents the right ear. During training, white ticks on the pleasure/pain bars and the window title show the ideal values actually used for learning; colored bars remain the translator's predictions.

## Reward translation

| Event | Source | Signal |
| --- | --- | --- |
| Health restored | Primitive, both modes | Pleasure = healed health / 40, at most 1 |
| Death (health reaches zero) | Primitive, both modes | One-time learning penalty **−8**, primitive pain saturates at 1 |
| Shot by enemy | Primitive, both modes | Pain pulse = damage / 25, at most 1 |
| Try to walk into a wall | Primitive, both modes | Pain = 0.1 × game speed × blocked fraction of requested movement |
| Missing health | Primitive, both modes | Continuous discomfort = 0.3 × missing-health fraction |
| Time passing | Physical, both modes | Lose 2 health per simulated second; existing low-health pain rises as health falls |
| Hit enemy | Learned teacher, training only | +0.2 |
| Kill enemy | Learned teacher, training only | Additional +0.6, so a lethal hit gives +0.8 |
| Ammo clip | Learned teacher, training only | +0.25 |
| Reach exit | Learned teacher, training only | +1 |
| Low-valued vision | Learned teacher, training only | Up to +100 × game speed per frame, scaled by darkness = 1 − mean world-ray RGB |
| Enter a new cell | Learned teacher, training only | **+24.0** once per cell per episode, excluding spawn |
| Enter a new 5×5 region | Learned teacher, training only | Additional **+8.0** once per region per episode, excluding spawn region |
| Stay in one spot | Learned teacher, training only | Continuous pain after a grace period, growing with duration |
| Walk through an explored cell | Neutral | No revisit penalty and no additional exploration reward |
| Miss an enemy with a fired projectile | Learned teacher, training only | 0.65 pain when it hits a wall or expires |

The staying rule uses physical displacement from a local anchor, not visit counts. Moving at least 0.65 tile resets it, including movement through previously explored cells. Turning, firing and pushing against a wall do not reset it. After 45 physics ticks of grace, pain ramps over 90 more ticks to `0.10 × gameSpeed` **each frame** (maximum 0.05/frame at the default half speed). At default pacing this starts after about 1.5 seconds and reaches its maximum after 4.5 seconds. This replaces the old occasional revisit pulse with sustained, time-scaled punishment. Revisits themselves have no penalty.

Exit completion requires reaching the exit alive; killing every enemy is optional. Pleasure targets are bounded to [0,256] and pain targets to [0,1]. Same-frame positive events sum and saturate at 256. Both exploration bonuses are eight times their previous values (3 per cell and 1 per region); entering a new region can earn 32 total. Repeated visits cannot farm either bonus. Each earned bonus is paid from a finite balance: 20% of the remaining credit per frame, rather than an unobservable one-frame grid-boundary spike. The undiscounted total remains 24 per new cell plus 8 per new region; the trace cannot mint additional reward while standing still. Terminal transitions flush remaining earned credit, subject to the overall pleasure cap. Miss penalties add to stationary pain and saturate at 1. Only actual player projectiles that fail to hit an enemy count: a shot in flight, an enemy projectile, or pressing fire with an empty magazine does not. Miss impacts produce spatial sound as perceptual evidence. Misses do not cause primitive pain, and play uses the frozen translator to infer their penalty.

**Train:** the main network learns from `ideal pleasure − ideal pain + primitive reward`, and the translator learns the same two ideal channels from sensory evidence, recent context, controls and sampled main neurons. Ideal values also drive gain and learned-pain inputs during training; predictions do not weaken the teaching signal. Reward probes are captured before the current action/feedback, so the current ideal label is not injected into its own evidence. Health/damage bonuses are not included in the translator's targets.

**Play:** the translator's weights and biases are frozen and its connection plasticities are zero. The main network continues learning from `predicted pleasure − predicted pain + primitive reward`. The game does not compute ideal exploration/stationary/miss labels, and neither teacher-labelled replay nor an oracle fallback is used. Primitive senses remain active.

Health continuously drains at **2 points per simulated second** in both modes. At the default half-speed physics and 60 updates/s this is **1 health per real second**; 100 starting health lasts roughly 100 seconds without healing or enemy damage. Health pickups still restore up to 40. Pausing stops simulation and health loss; headless runs use simulation time. Passive loss is not a projectile damage event: it produces no shot sound or damage pulse, and increases the existing low-health discomfort and learning cost instead. Zero health ends the episode and adds a one-time primitive death penalty of **−8** to that terminal learning transition, whether caused by passive drain or enemy fire. It adds to other primitive costs, requires no learned reward prediction, and clears on episode reset. Successful exits and time limits alone are not deaths. This creates survival pressure, but does not guarantee that the current learner discovers exploration. Restart the rebuilt app to activate the change.

The primitive learning reward is the healing pulse minus the damage pulse, minus wall-contact pain and a small time-scaled missing-health cost. Attempting movement blocked by a wall produces immediate primitive pain in both modes (0.05 per fully blocked frame at default half speed). Continued pushing keeps it active; diagonal sliding hurts in proportion to the blocked movement. Standing/turning beside a wall, unobstructed movement and cancelling opposite controls do not produce collision pain. It clears when the obstruction is no longer pushed against and on episode reset. Wall pain adds to the primitive pain sensation (total capped at 1) and directly reduces the main learning reward, without extra health damage or a reward-translator target. Positive primitive traces decay for perception/gain; the same pickup is not credited again each frame. Pain noise is sample-held for 12 frames and affects only the dedicated learned/primitive pain banks. Vision, PCM, FFT and controls are not corrupted. Pleasure increases main-network gain, capped at 4. A 1 Hz nonnegative clock input is also present.

## Networks and persistence

Live activations are retained between frames and advance **two synchronous connection hops per active frame** by default. Set `--propagation-steps 1` (or up to 32) to change the propagation clock. A frame supplies only current input; it does not clear neurons or instantly recompute all layers from scratch. CPU and Vulkan keep live state separate from prediction/training working buffers. Neither learning nor maze resets erase live state. Pausing the simulation pauses propagation.

The main network defaults to eight hidden layers of 512 logical units, adjacent connections and additional odd-to-odd skips. It has **4,133,376 stored connections and 14,052 nonnegative rate neurons**. Every input, hidden and output activation uses opposing nonnegative channel pairs; decoded action values may be signed outside the neuron interface. Weights/biases/gradients may be signed. Connection plasticity is a fixed multiplier on weight changes and is never optimized.

Input consists of the current first-person RGB line (plus its status pixels), 64 PCM samples and 32 FFT magnitudes **per ear**, the last action, explicit normalized health/total-ammo/loaded-ammo scalars, dedicated pain/pleasure banks and the clock. Legacy previous-view input ports remain zero. Three of the 64 former hidden-trace ports now carry explicit vitals: health/100, total rounds/104 (loaded plus reserve), and loaded rounds/8, clamped to [0,1]. The other 61 main trace ports remain zero; memory resides in live neuron activations. The reward system receives a current-pixel low-value summary through the first legacy trace port. This feature is routed to the dedicated visual readout and masked out of the event head; the other 63 ports stay zero. Eight button-score outputs are independently thresholded. Legacy output 0 is now a state-value baseline, and old combined-action output 8 is reserved; neither is a control. Predictive auxiliary outputs learn twelve luminance bins across the next world-ray line and the reward. The learner uses a separate state-value baseline with clipped temporal-difference targets, reward-dependent per-button targets, transition replay and a target network refreshed every 240 updates. Positive advantage nudges executed-button scores upward; negative advantage nudges them downward. Unpressed buttons have zero direct actor-loss weight: a bad off-policy exploratory action must not reinforce all the unpressed keys. The step uses a bounded tanh of advantage. This replaces the mutually exclusive action-max target. Training exploration samples raw button combinations, never an explicit wait action. Main weights update once per active frame; one in four updates samples replay. The smaller CPU-backed reward translator has 128 hidden units and two logical readouts. Its supervised replay includes separate exploration, missed-shot and stationary pools, with full weight for exploration examples and reduced weights for oversampled pain events and an explicit zero-pleasure replay pool to limit false rewards on neutral frames. Reward-only calibration uses predicted feedback as play does, while learning the teacher targets; ordinary policy training continues to apply ideal feedback directly. Eight extra reward inputs summarize recent pixel changes, perceptible translation and executed-action history; they use no coordinates, visited-cell table or ideal labels.

New installations use the repository-root `artifacts/maze/{main.ngb,reward.json,maze.json}` checkpoint, independent of launch directory. If the historical IDE checkpoint at `src/ArcadeLab/artifacts/maze` exists, it is consistently preferred to preserve that progress. Startup prints the absolute chosen path and warns when both historical copies exist. `--checkpoint PATH` always selects an explicit experiment. Autosave runs every 30 seconds and on normal exit/Ctrl+C. Both modes resume the same learned weights and counters. Legacy mono checkpoints gain right-ear and temporal-evidence input ports. Old grayscale visual ports map to red channels, with zero-weight green/blue edges added; all old stored weights, biases and plasticities are retained. The network can initially reproduce its prior response on replicated grayscale RGB inputs, but the actual perception has changed from a 2D raster to first-person colored rays. Continue with `--train` to adapt both networks; in `--play` only the main network learns while the reward head remains frozen. Session format 7 loads versions 1–6 as well and persists region counters, completion-based difficulty and the separately learned visual-reward coefficient. New saves include both networks' live neuron rates and propagation counters; these are restored on resume. Older checkpoints initialize live activity once because they contain no state snapshots. Use `--train --new` to deliberately restart; old arcade checkpoints remain separate. `--checkpoint PATH` selects another experiment and `--no-save` permits a temporary run. Reloading starts a new maze while restoring saved neural activity; exact physics, random state, perceptual-processor context and replay history are not serialized. Individual model files are replaced atomically, but the directory is not a transactional snapshot: avoid simultaneous writers.

## Verification and limitations

```bash
dotnet build -c Release
dotnet run --project tests/NeuralGraph.Checks -c Release -- --require-vulkan
```

The checks cover numerical gradients, CPU/Vulkan parity, nonnegative neurons, fixed plasticity, saves, projectile collision, pickups, repeated visits, and the distinction between training and realtime play rewards. They also check audio boundary continuity, fixed note durations across buffer sizes, overlapping voices and observer-rendering isolation. A standalone stream check can run with `ALSOFT_DRIVERS=null dotnet run --project tests/NeuralGraph.Checks -c Release -- --audio-stream`. [Initial maze results](artifacts/MAZE_RESULTS.md), [graphics/audio verification](artifacts/MAZE_PRESENTATION_AUDIO.md), [large-maze/missed-shot training](artifacts/MAZE_LARGE_MISSES.md), [stereo/exploration reward training](artifacts/MAZE_STEREO_EXPLORATION.md), [first-person color vision verification](artifacts/MAZE_COLOR_VISION.md), [persistent propagation verification](artifacts/CONTINUOUS_PROPAGATION.md), and [threshold controls/exploration](artifacts/THRESHOLD_EXPLORATION.md) record the measured training and validation runs.

The learning objective uses independent button scores, a state-value baseline and auxiliary next-view/reward prediction; persistent activation propagation is implemented, but this does not constitute a full predictive-coding error-neuron inference algorithm or temporal backpropagation. This is an experimental learner, not a solved maze agent. A brief starter run does not establish reliable navigation or reward translation. Sparse kills/exits need substantially more experience. Novelty and stationary inference are partially observable and use finite neural context rather than a privileged visited-cell table at play time. A frozen translator can misread new situations or changing main-network representations, so reward hacking remains possible. The main network receives explicit normalized health and ammunition in addition to the visible status pixels. The reward translator still receives their perceptual evidence rather than these new scalar ports. The observer map, coordinates, raw ray distances, event counters and teacher targets are never directly passed as neural features.

The activity panel shows a readable sampled overview of the main network: **input on the left, H1 through the hidden layers, output on the right**. Arrows show propagation direction. Cyan edges have positive weights, red edges negative weights; brightness scales with absolute weight as `abs(w)/(abs(w)+0.1)`, and larger magnitudes use thicker lines. Dashed curved edges are skip connections. Each circle is one actual logical unit split into green/blue halves for its two nonnegative rate neurons. Node brightness clips at 1 for display, while hover shows unclipped rates. Hover a node for its ID, both rates and bias; hover an edge for its endpoints, signed weight and fixed plasticity. Weight snapshots refresh twice per second. The input bank shows eight actual units out of 2,907, and each hidden column shows six actual units out of its full width; labels give both sample and actual counts. The 23 outputs are individually labeled: eight keys, fourteen auxiliary outputs (state value, reward and twelve future-view bins), and one unused compatibility port. There are 1,296 current RGB inputs: 1,152 world-ray color channels and 144 status-color channels. Historical zeroed ports remain allocated. The header shows actual counts. Eight key outputs are separated from auxiliary outputs, with the compatibility port labeled UNUSED.

A weight multiplies a source unit's decoded value (`A+ - A-`); it is separate from current activity. A negative weight is legal even though physical neuron rates are nonnegative. The main and head loss readouts report the latest batch's weighted squared loss (`0.5 * sum(weight * (prediction-target)^2)`, averaged over samples). They are training objectives, not neuron activations. There is no local predictive-error neuron signal in this implementation. A frozen reward head shows FROZEN rather than a misleading zero loss.

Hit/kill events are shown for two seconds with cumulative counters and the predicted pleasure at impact. In training, the readout also shows the ideal combat contribution: +0.2 per hit plus +0.6 per kill, so a lethal hit earns +0.8 before other rewards and the combined pleasure cap. Green/red bars show predictions; white markers show ideal training targets. Training applies ideal rewards directly even if predictions are wrong. Play uses frozen-head predictions plus primitives. Combat events have dedicated supervised replay so rare hits and kills compete less with abundant neutral samples; this improves training coverage but does not guarantee accurate play-time combat recognition. No weights were reset or retrained merely by adding this viewer.


The audit in [MAZE_NETWORK_AUDIT.md](artifacts/MAZE_NETWORK_AUDIT.md) measured the existing all-keys behavior and documents the corrected actor update, historical checkpoint-path issue and graph-count mismatch. Raw per-key scores appear above the executed-key indicators, with THRESHOLD/EXPLORATION/MANUAL identifying control origin. Thresholded play is deterministic, not independent random key presses. Absolute predicted/ideal values accompany normalized reward bars. Multiplying both a reward and its bar maximum by eight leaves the normalized width unchanged; the exploration readout now shows the 24/8 schedule and actual ideal payout/remaining credit in training. Frozen play rewards require further reward-network training to reflect changed targets. No historical checkpoint was reset or rewritten by this audit.


Error diagnostics print every 60 updates and immediately on damage, death or initial wall contact, in both GUI and headless runs. `ERROR` reports actual pre-update weighted loss, signed TD error (`value target - prediction`), RMSE for executed-button targets, and RMSE for the twelve next-view prediction bins. `sample=current/replay` identifies which transition was used; its pain cost can differ from the current frame. `PAIN` reports the current primitive sensation and applied learned pain, separate projectile/wall/death/missing-health costs, the combined negative reward contribution and net learning reward, plus health and ammunition. The viewer shows these errors beneath its reward bars.

`value_loss_without_pain_target` keeps the sampled prediction and bootstrap fixed, removes its additive pain cost from the value target, applies the same target clamp, and computes half the squared error. It isolates the direct target shift. It does **not** rerun the network with pain inputs disabled, remove historical effects of pain, or measure a causal response of all neurons. Pain can increase or decrease squared error depending on the current prediction; no rule forces pain to increase network error. These are surrogate learning errors, not local predictive-coding error-neuron activations. Diagnostics add no inference passes and do not alter training targets. Main vitals reuse existing ports, so checkpoint shapes and stored weights are preserved, but learning must adapt to the newly active features.


The visual reward now prefers **low RGB values**, replacing the previous color-diversity/structure objective. Its score is `darkness = 1 - mean(worldRayRGB)`, using only the 384 world rays (1,152 channels), clamped to [0,1]. HUD pixels are excluded. Black scores 1, white scores 0, and a uniform value of 0.25 scores 0.75. Color diversity and spatial patterns earn no separate bonus: scenes with the same mean RGB intensity have the same score. Existing distance shading contributes to those raw values, so darker distant views can score higher.

This is **learned reward-system supervision, not a primitive reward**. Alive, nonterminal training frames add `100 * gameSpeed * darkness²` to ideal pleasure and teach the separate visual readout. The darkness score is squared before both supervision and inference. At default speed, darkness 0.5 gives a target contribution of 12.5 (previously 25), while black remains 50 and white remains 0. The event head learns the remaining pleasure target and pain. The visual readout predicts `100 * learnedWeight * gameSpeed * darkness²`, with a nonnegative coefficient fitted during training on the unit-scale target (before the 100× multiplier). Existing learned coefficients therefore retain their meaning, and frozen predictions receive the full multiplier too. Total predicted pleasure is `clamp(nonnegativeEventPleasure + predictedVisualPleasure, 0, 256)`. Primitive pleasure, pain, health effects and their learning costs receive no direct darkness term.

Both reward components freeze in play. Play supplies the current low-value summary as evidence and uses the stored coefficient; it does not add an ideal darkness reward. An untrained zero coefficient yields no visual reward even in a black scene. Older trained scalar coefficients remain dimensionally compatible because the supervised proportional mapping retains the same scale; existing event-head associations may still need further training. Version-7 sessions save the coefficient and sample count in maze.json, so reward.json alone is not the complete composed reward system. The viewer labels the current score DARKNESS and shows predicted visual reward beside the ideal training bonus. Console output uses `visual_darkness`.

At default half speed the maximal target contribution is **50 per active frame**, exactly 100 times its previous value. At maximum game speed it is 200; the combined pleasure cap is raised to 256 so darkness alone is not clipped. Main gain is clamped to the backend-supported maximum of 4, and value targets use ±16,384 to accommodate the larger return scale. The maze completion curriculum is unchanged. Tests cover black/white/dim images, equal-mean color invariance, HUD exclusion, time scaling, frozen untrained play, learned predictions and absence of a primitive darkness bonus. Restart the rebuilt executable to apply the objective change.


A purple **MAIN LOSS** bar sits directly beneath the network graph. Its width uses a fixed logarithmic mapping `clamp(log10(1 + loss) / 6, 0, 1)` over 0 to 1,000,000, with ticks at 1, 100, 10,000 and 1,000,000; the exact current loss is printed above it. The mapping is display-only and never changes learning. This is the current main-network weighted training loss, not the proposed sum of explicit error-neuron activities or variational free energy.
